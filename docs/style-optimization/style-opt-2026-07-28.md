## 三、具体修改内容

### 3.1 统一 select 元素交互态（3 个工具页面）

**背景**：2026-07-27 的报告中，已经为 `qr.astro` 的 `.qrtool__select` 补全了 `hover` 与 `focus-visible` 交互态。但审查发现，同属工具矩阵的 `json.astro`、`hash.astro`、`password.astro` 三个页面的 select 元素仍缺少这两个状态，造成工具页表单元素交互反馈不一致。

本次修改沿用 2026-07-27 报告确立的样式基线，为以下三个 select 选择器补全 `hover`、`focus-visible` 与 `transition` 三条规则：

| 文件 | 选择器 | 修改内容 |
|------|--------|----------|
| `src/pages/json.astro` | `.jsontool__indent select` | 新增 `cursor: pointer`、`transition`，及 `:hover` / `:focus-visible` 规则 |
| `src/pages/hash.astro` | `.hashtool__select` | 新增 `transition`，及 `:hover` / `:focus-visible` 规则 |
| `src/pages/password.astro` | `.pwtool__select` | 新增 `transition`，及 `:hover` / `:focus-visible` 规则 |

**统一样式模板**（三个页面采用完全一致的交互态定义）：

```css
/* hover / focus-visible：与 qrtool__select 保持一致，补全交互态可供性提示 */
.xxxtool__select:hover {
  border-color: var(--color-primary);
}

.xxxtool__select:focus-visible {
  outline: none;
  border-color: var(--color-primary);
  box-shadow: var(--focus-ring);
}
```

**设计要点**：

1. **复用全局焦点环令牌**：三处 `focus-visible` 均使用 `global.css` 中定义的 `--focus-ring` 变量（`0 0 0 3px var(--color-primary-ring)`），与 `.btn`、`.tools__filter`、`.pagination__page` 等全局组件焦点态完全一致，避免局部硬编码造成的视觉差异。
2. **过渡曲线统一**：三处 `transition` 使用 `var(--transition-fast)`（0.12s ease-out），与全站表单元素过渡节奏一致。
3. **hover 仅改边框色**：不改变背景色，避免与 `:focus-visible` 的焦点环叠加时产生视觉噪音。
4. **暗色模式自动适配**：所有颜色引用 CSS 变量，暗色模式通过 `:root` 令牌覆盖自动生效，无需额外规则。
5. **可达性提升**：`:focus-visible` 仅在键盘导航时触发，鼠标点击不显示焦点环，符合 WCAG 2.2 焦点可见要求且不干扰鼠标用户。

### 3.2 临时补全并行任务空文件 frontmatter

**问题**：运行 `npm run build` 时，Astro 在 content sync 阶段报错：

```
[InvalidContentEntryDataError] blog → randomness-generation-toolchain-guide data does not match collection schema.
  title: Required
  description: Required
  pubDate: Invalid date
```

**根因**：`src/content/blog/randomness-generation-toolchain-guide.md` 是并行自动开发任务新建的空文件（0 字节），缺少 `content.config.ts` 要求的 `title` / `description` / `pubDate` frontmatter 字段，与本次样式优化无关。

**处理**：为该空文件临时添加最小 frontmatter（`title` / `description` / `pubDate` / `tags: []` / `draft: true`）解除构建阻塞。该文件实际内容由并行自动开发任务负责填充，后续会自然覆盖此占位 frontmatter。设置 `draft: true` 确保占位期间不会出现在生产博客列表中。
